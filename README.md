# NPL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования

## Языки

Ada, Clojure, D, Elixir, Erlang, F#, Groovy, Haskell, Julia, Kotlin, Nim,
Objective-C, OCaml, Perl, Prolog, Rust, Scala, Scheme, Swift, Zig.

## Тема 1. Многопоточность
Папка: `1_threads/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Параллельное вычисление сумм строк и столбцов матрицы | Ada | 1_task_1_ada |
| 2 | Параллельное транспонирование блочной матрицы | Kotlin | 1_task_2_kotlin |
| 3 | Параллельный поиск палиндромных подстрок фиксированной длины | Rust | 1_task_3_rust |
| 4 | Параллельный поиск групп анаграмм по словарю | Elixir | 1_task_4_elixir |

1.1 Параллельное вычисление сумм строк и столбцов матрицы (Ada). Матрица целых чисел читается из текстового файла (первая строка — размеры N M). Строки делятся на горизонтальные полосы, каждая полоса обрабатывается отдельной Ada-задачей (task): считаются суммы строк и частичные суммы столбцов. Частичные результаты передаются в защищённый объект (protected object), где объединяются. В конце проверяется, что сумма сумм строк равна сумме сумм столбцов, печатается максимальная сумма строки и время работы для 1 и N задач.

1.2 Параллельное транспонирование блочной матрицы (Kotlin). Квадратная матрица целых чисел размера N×N (N кратно размеру блока B) генерируется или читается из файла и хранится в виде сетки блоков B×B. Транспонирование выполняется в пуле потоков (ExecutorService): задача обрабатывает пару симметричных блоков (i, j) и (j, i), транспонирует каждый и меняет их местами; диагональные блоки транспонируются на месте. Результат записывается в новую матрицу либо на месте — по параметру. Проверяется, что (Aᵀ)ᵀ = A и что A[i][j] = Aᵀ[j][i] для случайной выборки элементов. Выводится время последовательного и параллельного транспонирования для разного числа потоков и размеров блока.

1.3 Параллельный поиск палиндромных подстрок фиксированной длины (Rust). Программа читает текст из файла (или генерирует случайную строку над небольшим алфавитом) и ищет все позиции, где начинается подстрока-палиндром заданной длины L. Строка делится на фрагменты между потоками (std::thread) с перекрытием в L−1 символов, чтобы не потерять подстроки на границах; каждый поток возвращает найденные позиции через канал (mpsc) главному потоку. Главный поток объединяет результаты без дубликатов, печатает общее число палиндромов, первые десять позиций с подстроками и самую частую палиндромную подстроку. Результат сравнивается с последовательным поиском, выводится время обоих вариантов.

1.4 Параллельный поиск групп анаграмм по словарю (Elixir). Файл-словарь (по одному слову в строке) делится на куски, каждый кусок обрабатывает отдельный процесс-воркер: слова группируются по ключу из отсортированных букв. Процесс-коллектор получает сообщения от воркеров и сливает группы. Печатается число групп размера не меньше 2 и пять самых больших групп.

## Тема 2. Алгоритмические задачи
Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Рекурсивная генерация замощений доски (рекурсия) | Haskell | 2_task_1_haskell |
| 2 | Решение нонограммы перебором с возвратом (рекурсия) | Prolog | 2_task_2_prolog |
| 3 | Максимальное паросочетание в двудольном графе | OCaml | 2_task_3_ocaml |
| 4 | Рекурсивное вычисление расстояния между деревьями (рекурсия) | Scheme | 2_task_4_scheme |

2.1 Рекурсивная генерация замощений доски (Haskell). Прямоугольная доска N×M (возможны заранее заданные запрещённые клетки) замащивается доминошками 1×2 без наложений и пропусков. Рекурсивная функция находит первую свободную клетку, пробует положить доминошку горизонтально и вертикально и продолжает на оставшейся части; результат — ленивый список всех замощений. Программа печатает общее число замощений и первое найденное в виде текстовой схемы, где каждая доминошка обозначена своей буквой. Если замощений нет (например, нечётное число свободных клеток), выводится соответствующее сообщение.

2.2 Решение нонограммы с возвратом (Prolog). Нонограмма задаётся подсказками для строк и столбцов (списки длин блоков). Предикат с бэктрекингом перебирает для каждой строки все расположения блоков, согласующиеся с подсказкой, и после каждой выбранной строки проверяет частично заполненные столбцы на совместимость с их подсказками, отсекая заведомо неверные ветви. Состояние (уже выбранные строки) передаётся явно через аргументы предикатов, без изменяемых глобальных фактов. Программа выводит решение в виде сетки из символов # и ., сообщает о противоречивой нонограмме и о числе решений, если их больше одного.

2.3 Максимальное паросочетание в двудольном графе (OCaml). Граф задаётся размерами долей и списком рёбер «левая вершина — правая вершина». Паросочетание строится алгоритмом Куна: для каждой левой вершины ищется увеличивающая цепь поиском в глубину с массивом посещённых вершин. Структуры данных (списки смежности, массивы пар) реализуются самостоятельно. Программа выводит размер максимального паросочетания, сами пары и список вершин, оставшихся без пары, а также проверяет, что никакая вершина не используется дважды.

2.4 Рекурсивное вычисление расстояния между деревьями (Scheme). Два упорядоченных помеченных дерева задаются S-выражениями вида (a (b) (c (d))). Рекурсивно вычисляется расстояние редактирования деревьев — минимальное число операций вставки узла, удаления узла и замены метки, превращающих одно дерево в другое; рекурсия идёт по лесам (списку поддеревьев), промежуточные результаты запоминаются в таблице (мемоизация). Программа печатает расстояние и одну из минимальных последовательностей операций. Сообщается об ошибке при неверном S-выражении (незакрытая скобка, пустой ввод).

## Тема 3. Ввод/вывод в консоль и файл
Папка: `3_io/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | Слияние нескольких CSV-файлов с общим заголовком | Perl | 3_task_1_perl |
| 2 | Поиск повторяющихся абзацев по хешам | Nim | 3_task_2_nim |
| 3 | Утилита «последние N строк» с чтением с конца файла | Objective-C | 3_task_3_objc |
| 4 | Резервное копирование файлов с проверкой целостности | Zig | 3_task_4_zig |

3.1 Слияние нескольких CSV-файлов с общим заголовком (Perl). На вход подаётся список CSV-файлов с одинаковым заголовком. Разбор учитывает кавычки, запятые и переводы строк внутри полей. В итоговый файл записывается общий заголовок плюс служебный столбец _source с именем файла-источника, порядок записей сохраняется. Если заголовки файлов не совпадают, программа сообщает, какие именно столбцы отличаются, и завершается с ошибкой.

3.2 Поиск повторяющихся абзацев по хешам (Nim). Программа принимает путь к текстовому файлу, делит его на абзацы (разделитель — пустая строка), нормализует каждый (обрезка пробелов, сведение пробельных символов к одному пробелу, приведение к нижнему регистру) и вычисляет хеш — самостоятельно реализованный FNV-1a (64 бита). Абзацы с одинаковым хешем группируются, и для каждой группы текст сравнивается напрямую, чтобы исключить коллизии. В консоль и в отдельный файл отчёта выводятся группы повторов: номера абзацев, число повторений и начало текста. При отсутствии исходного файла программа сообщает об ошибке.

3.3 Утилита «последние N строк» с чтением с конца файла (Objective-C). Программа получает имя файла и число N и выводит последние N строк, читая файл кусками с конца через NSFileHandle (без загрузки файла целиком в память). Корректно обрабатываются окончания строк LF и CRLF, пустой файл и случай, когда строк меньше N. Дополнительно печатается байтовое смещение начала первой выведенной строки.

3.4 Резервное копирование файлов с проверкой целостности (Zig). Программа получает путь к исходному файлу и создаёт его резервную копию в указанном каталоге. Копирование выполняется блоками, без загрузки всего файла в память. Для исходного и скопированного файлов вычисляется контрольная сумма на основе самостоятельно реализованного алгоритма CRC32. Результаты записываются в отдельный файл-манифест. Предусмотрен режим проверки резервной копии, в котором программа сравнивает контрольные суммы и сообщает о повреждении данных.

## Тема 4. Клиент-серверное взаимодействие
Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | TCP-сервер управления таймерами | Erlang | 4_task_1_erlang |
| 2 | TCP-калькулятор с переменными клиента | Julia | 4_task_2_julia |
| 3 | TCP-сервер таблицы лидеров | Scala | 4_task_3_scala |
| 4 | TCP-сервер операций над полиномами | D | 4_task_4_d |

4.1 TCP-сервер управления таймерами (Erlang). Сервер на gen_tcp принимает подключения; на каждого клиента запускается отдельный процесс. Команды: START имя секунды, STOP имя, LIST, QUIT. Каждый таймер — отдельный процесс, который по истечении времени (erlang:send_after или receive ... after) отправляет владельцу-клиенту сообщение EXPIRED имя; имена таймеров уникальны в пределах клиента. LIST показывает активные таймеры и оставшееся время. При отключении клиента его таймеры останавливаются, неизвестные команды и повторное имя таймера дают текст ошибки.

4.2 TCP-калькулятор с переменными клиента (Julia). Каждый клиент обслуживается своей задачей; команды: SET имя значение, EVAL выражение, VARS, QUIT. Выражения — числа, переменные, + - * /, скобки; разборщик пишется вручную, eval не используется. У каждого клиента своя таблица переменных. Сервер возвращает результат или текст ошибки (деление на ноль, неизвестная переменная, синтаксис).

4.3 TCP-сервер таблицы лидеров (Scala). Команды: SUBMIT игрок очки, TOP n, RANK игрок, RESET игрок, QUIT. Сервер хранит таблицу результатов в общей структуре под блокировкой; для каждого игрока учитывается лучший результат, при равенстве очков выше стоит тот, кто набрал их раньше. TOP возвращает n лучших с местами, RANK — место и очки игрока. Каждое подключение обрабатывается в отдельном потоке, при неверной команде, нечисловых очках или неизвестном игроке возвращается текст ошибки.

4.4 TCP-сервер операций над полиномами (D). Сервер принимает несколько подключений; у каждого клиента своя таблица полиномов с целыми коэффициентами. Команды: DEF имя коэффициенты, ADD a b, MUL a b, DIFF a, EVAL a x, SHOW a, QUIT. Результаты операций сохраняются под новым именем или выводятся в виде 3x^2 - 2x + 1; арифметика полиномов реализуется самостоятельно. Предусмотрены сообщения об ошибках (неизвестное имя, неверные коэффициенты, пустой полином) и корректное завершение соединения.

## Тема 5. Конвертация данных из одного формата в другой
Папка: `5_convert/`

| № | Задача | Язык | Ветка |
| --- | --- | --- | --- |
| 1 | TOML (подмножество) в JSON | Clojure | 5_task_1_clojure |
| 2 | BibTeX в JSON | F# | 5_task_2_fsharp |
| 3 | RSS или Atom в Markdown | Swift | 5_task_3_swift |
| 4 | BMP в PPM | Groovy | 5_task_4_groovy |

5.1 TOML (подмножество) в JSON (Clojure). Собственный разборщик TOML поддерживает таблицы [section] и вложенные [a.b.c], пары ключ = значение: строки в кавычках, целые и вещественные числа, true/false, массивы [1, 2, 3], комментарии #. Результат — JSON-объект с корректным экранированием и отступами, вложенность таблиц превращается во вложенные объекты.

5.2 BibTeX в JSON (F#). Собственный разборщик BibTeX читает записи вида @article{ключ, поле = {значение}, ...}: тип записи, ключ цитирования, поля со значениями в фигурных скобках (в том числе вложенных), в кавычках или числами; строковые макросы @string и комментарии пропускаются либо подставляются. Результат — JSON-массив объектов с полями type, key и остальными полями записи; список авторов разбивается по and в массив строк. Выход корректно экранируется и форматируется с отступами, для некорректной записи сообщается номер строки.

5.3 RSS в Markdown (Swift). Программа читает XML-файл RSS-ленты и разбирает его. Из ленты извлекаются заголовок и описание, а для каждой записи — заголовок, ссылка, дата публикации и описание (HTML-теги в описании удаляются). Результат записывается в Markdown-файл: заголовок первого уровня с названием ленты, затем для каждой записи заголовок второго уровня со ссылкой, дата и текст. Специальные символы Markdown экранируются; при неверном XML или если файл не является RSS-лентой, выводится ошибка.

5.4 BMP в PPM (Groovy). Программа считывает бинарный BMP-файл, разбирает заголовок, получает ширину, высоту, глубину цвета и данные пикселей. Поддерживается несжатый BMP с глубиной цвета 24 бита. Учитываются выравнивание строк пикселей и порядок хранения строк в BMP. Изображение преобразуется в формат PPM P6 с заголовком, содержащим размеры изображения и максимальное значение цвета 255. Результат записывается в бинарный файл.
