# Задача 1.2 — Параллельное транспонирование блочной матрицы (Kotlin)

## Условие

Квадратная матрица целых чисел размера `N×N` (`N` кратно размеру блока `B`)
читается из текстового файла (первая строка — размеры `N B`) или генерируется
случайно. Матрица хранится в виде сетки блоков `B×B`. Транспонирование
выполняется в пуле потоков (`ExecutorService`): каждая задача обрабатывает пару
симметричных блоков `(i, j)` и `(j, i)`, транспонирует каждый и меняет их
местами; диагональные блоки транспонируются на месте. В конце проверяется, что
`(Aᵀ)ᵀ = A` и что `A[i][j] = Aᵀ[j][i]` для случайной выборки элементов.
Печатается время последовательного и параллельного транспонирования для разного
числа потоков и размеров блока.

## Что делает код

1. Читает `N`, `B` и элементы матрицы из `input.txt` (или генерирует случайную
   матрицу, если файл не найден).
2. Представляет матрицу как сетку блоков `Array<Array<IntArray>>`: каждый блок —
   одномерный массив размера `B×B`, доступ к элементам через `get`/`set` с
   вычислением координат блока (`r / b`, `c / b`) и смещения внутри него
   (`r % b`, `c % b`).
3. Функция `transposeBlockInPlace` транспонирует один блок на месте, меняя
   элементы симметрично относительно его главной диагонали.
4. Функция `transposeSequential` проходит по верхней треугольной части сетки
   блоков, транспонирует пару симметричных блоков и меняет их местами;
   диагональные блоки обрабатываются отдельно.
5. Функция `transposeParallel` отправляет каждую пару блоков в пул потоков
   `Executors.newFixedThreadPool` через `submit`, сохраняет `Future` и дожидается
   всех задач через `get()`, перехватывая `InterruptedException` и
   `ExecutionException`; в `finally` гарантированно вызывается `shutdown` и
   `awaitTermination`.
6. Функция `verify` проверяет корректность двумя способами: случайная выборка из
   10 000 элементов на условие `A[i][j] == Aᵀ[j][i]`, и полное поблочное
   совпадение `(Aᵀ)ᵀ` с исходной матрицей.
7. Функции `benchSequential` и `benchParallel` усредняют время по 5 прогонам;
   перед замерами выполняется warm-up для активации JIT-компилятора JVM.
8. Прогон повторяется для трёх размеров блока — `B = 32`, `B = 64`, `B = 128`,
   для каждого выводится таблица времени и ускорения при 1, 2, 4, 8 и 16 потоках.

Все размеры и индексы защищены проверками `require`, поэтому некорректный вход
или выход за границы матрицы приводят к понятной ошибке, а не к тихому
повреждению данных.
